## 2. Agent recording lifecycle and artifact delivery — WEB-17

T3 exposes `preview_recording_start` and `preview_recording_stop` in [tools.ts](../../t3code/apps/server/src/mcp/toolkits/preview/tools.ts), routes them through [handlers.ts](../../t3code/apps/server/src/mcp/toolkits/preview/handlers.ts), and targets the owning thread/tab in [PreviewAutomationHosts.tsx](../../t3code/apps/web/src/components/preview/PreviewAutomationHosts.tsx). [browserRecordingScope.ts](../../t3code/apps/web/src/browser/browserRecordingScope.ts) resolves stop targets without guessing among multiple recordings. The recording holds the surface active for its full lifetime.

PiStation already has human recording in [PreviewWebViewSurface.xaml.cs](../src/PiStation.App/Views/Controls/PreviewWebViewSurface.xaml.cs), but its [Pi tool](../src/PiStation.App/PiExtensions/pistation-browser.ts) and [wire operations](../src/PiStation.Protocol/Models/BrowserAutomation.cs) lack recording actions. Extract a shared recording owner used by human and agent controls; add typed start/stop/status results through the existing host/client bridge. Bind each recording to environment, thread, stable tab and controller/session identity. Keep its surface rendered after the initiating request finishes and while another panel/thread is selected. Define behavior for repeated start/stop, tab closure, permission revocation, disconnect, cancellation during startup/encoding, and automatic duration limits. Cleanup from an old request must not stop a newer recording.

T3 returns an artifact ID, path, MIME type, size and creation time. Adapt this to PiStation's remote boundary: a video created on the Windows client is not automatically readable by Pi on a remote host. Provide bounded transfer or a scoped artifact retrieval path and report only a location the owning runtime can actually use. The current browser result allows bounded JSON plus a screenshot; it is not a general video transport. Do not put an arbitrarily sized recording into its screenshot field.

Acceptance: human/agent conflicts, explicit/implicit stop targets, two tabs/threads/environments, start-stop races, cancellation/late completion, disposal on disconnect or access removal, hidden/background capture, zero-frame/encoder failure, automatic limit handling, and artifact retrieval locally and over HTTPS/SSH. ## 3. Recording frame rates and capture quality — WEB-09

T3's [settings contract](../../t3code/packages/contracts/src/settings.ts) offers 30/60 FPS with a default of 30, surfaced in [IntegrationsSettings.tsx](../../t3code/apps/web/src/components/settings/IntegrationsSettings.tsx). Its recording module requests a tab media stream with a maximum frame rate, then uses `MediaRecorder`, selecting a supported encoder and retaining the actual MIME type. The desktop [preview manager](../../t3code/apps/desktop/src/preview/Manager.ts) arms the specific tab, coordinates capture, and holds its activity lease.

PiStation currently captures PNG files at 1–12 FPS, caps duration at two minutes, takes at most 1,440 frames and assembles image clips into an MP4. Raising only the clamp leaves the frame-count, disk, timing and encoder assumptions inconsistent. First measure this backend, then select and verify a Windows capture/encoding path that can sustain the requested rates while preserving tab ownership and background behavior. The Electron capture API cannot simply be copied into WinUI; choosing its native replacement is an implementation investigation, not a claim made by this review.

Persist requested FPS, preserve measured frame timing, report effective capture where it falls short, and bound duration, bytes and queued frames. Test moving content, different viewports, hidden tabs, cancellation, dropped frames and resource use. A selectable “60 FPS” label alone is not completion.

## 4. Native Pi runtime preferences — PI-20, PI-21

These are Pi capabilities, so T3's other provider adapters do not supply the actual runtime contract. Pi's [SettingsManager](<../../Pi Agent/packages/coding-agent/src/core/settings-manager.ts>) exposes a transport setting defaulting to `auto`; its [SDK](<../../Pi Agent/packages/coding-agent/src/core/sdk.ts>) supplies it when creating the agent. The inspected RPC command definitions do not expose a transport setter. Choose a supported settings/SDK route and report whether an existing runtime has applied the saved change; do not invent a CLI/RPC flag or silently rewrite unrelated settings.

Pi [startup](<../../Pi Agent/packages/coding-agent/src/main.ts>) recognizes `--offline`/`PI_OFFLINE` and sets `PI_SKIP_VERSION_CHECK` when offline. Its RPC startup skips the background catalog refresh in offline mode; this must not be presented as preventing model requests or all networking. [telemetry.ts](<../../Pi Agent/packages/coding-agent/src/core/telemetry.ts>) applies `PI_TELEMETRY` over the stored setting. Provider adapters such as [openai-responses.ts](<../../Pi Agent/packages/ai/src/api/openai-responses.ts>) consume `PI_CACHE_RETENTION=long`; describe its provider-specific effect rather than promising universal behavior.

Use the existing host runtime settings and saved/effective/restart pattern in [PiRuntimeSetup.cs](../src/PiStation.Protocol/Models/PiRuntimeSetup.cs), [PiRuntimeSettingsStore.cs](../src/PiStation.Host/PiRuntimeSettingsStore.cs) and [ShellViewModel.Setup.cs](../src/PiStation.App/ViewModels/ShellViewModel.Setup.cs). Add discoverable controls, defaults/unmanaged states, conflict rules for existing raw arguments/environment entries, revision-aware saves and remote host ownership. Confirm flag truthiness/presence semantics against Pi before encoding an “off” value; setting an environment variable to the string `0` is not uniformly equivalent to removing it in all Pi paths.

Acceptance: persistence/restart, effective state, inherited versus explicit values, legacy conflicts, unavailable runtime support, read-only remote denial, and isolated Pi tests without live provider charges. Fresh authentication/provider onboarding remains PI-09/DEL-06.

## 5. Installed-browser import — WEB-07

T3's [Sources.ts](../../t3code/apps/desktop/src/preview/BrowserImport/Sources.ts) enumerates browser profiles, [CookieDatabase.ts](../../t3code/apps/desktop/src/preview/BrowserImport/CookieDatabase.ts) snapshots the database consistently through a read-only source connection, and [BrowserImport.ts](../../t3code/apps/desktop/src/preview/BrowserImport/BrowserImport.ts) validates availability and writes the selected target profile. [BrowserImportWizard.tsx](../../t3code/apps/web/src/components/settings/BrowserImportWizard.tsx) handles user selection and target-profile completion/recovery. The [contract](../../t3code/packages/contracts/src/browserImport.ts) separates unavailable reasons from attempted-import failures and reports imported/skipped counts.

Port the Windows source behavior for Firefox and compatible Helium. Use the user's selected source/profile and an environment-scoped WebView2 destination. Preserve host-only/domain, path, secure, HTTP-only, expiry and SameSite semantics; do not widen a cookie while translating APIs. [FirefoxCookies.ts](../../t3code/apps/desktop/src/preview/BrowserImport/FirefoxCookies.ts) contains schema-dependent expiry and SameSite handling. Helium needs its supported Windows key/database handling, with unsupported or undecryptable records reported as skipped. The reviewed source does not support general Chrome/Edge import on Windows.

Reuse the current profile UI and cookie writer where their semantics match, adding capability checks for anything WebView2 cannot preserve. The source browser must remain unmodified. Keep cookie values out of logs, transcripts and ordinary RPC metadata; import is an explicit local desktop action, not a remote scan of another computer. Test absent/running sources, invalid profile selection, database snapshots, cookie semantics, partial results, target-profile persistence failure/cleanup, and restart/environment isolation with fixtures before attended real-browser acceptance.
