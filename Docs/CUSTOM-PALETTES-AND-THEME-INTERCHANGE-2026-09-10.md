## Source comparison

Reviewed local T3 `0a590fa01`, especially `packages/shared/src/themePalettes.ts`, `apps/web/src/themePalette.ts`, `vscodeThemeImport.ts`, and `components/settings/{ThemeEditorPanel,ThemeImportDialog,ThemeSettings,themeEditorStore,themeInspector}`. T3 edits a live unsaved palette, preserves the draft across navigation, restores saved colors when preview ends, validates a version-1 JSON interchange format, and maps inspected paint back to a color role. Its 57 shared roles and light/dark variants form the interchange contract. T3's default color data is retained in `ThemeDefaults.json` for partial T3 imports; new native palettes start from PiStation's existing defaults.

T3 converts VS Code themes on import and exports the resulting T3 theme. It maps workbench colors, flattens alpha over the destination surface, and protects foreground readability. PiStation follows that workflow for standalone JSON/JSONC files. Syntax-token rules, extensions, marketplace discovery and inherited external files are not executed or imported. This is palette conversion, not VS Code extension compatibility. T3's guided palette generator and browser CSS inspector are adapted to explicit native color editing and native brush inspection.

Reviewed Pi 0.85.0 at `../Pi Agent`, including `docs/themes.md`, `theme-json.ts`, `theme-schema.json` and built-in palettes. Pi values can be hex colors, ANSI indices, variable references, or an empty string meaning the terminal default. PiStation resolves those color resources into a native palette. TUI syntax colors, thinking borders, terminal component geometry and Pi's theme selection/hot reload do not control WinUI. Importing colors does not modify the Pi runtime configuration or an installed Pi theme.

## Behavior and boundaries

- Settings → Appearance → Custom palettes provides create, edit, duplicate, apply, delete and native reset. Both appearances can be edited. Names are bounded, invalid colors leave the previous preview intact, and a native color picker complements literal color input.
- Preview changes the current window without saving. A window banner exposes Cancel when settings are closed. Save validates and commits the palette; Cancel restores the saved palette. A single-appearance palette uses the native fallback when the user switches to an appearance it does not contain.
- The inspector resolves actual native background, foreground or border brushes to editable roles by resource identity rather than RGB equality. Pointer inspection and keyboard selection of visible named areas return to the editor. Embedded browser page content and terminal internals are separate surfaces; their supported palette colors can be edited by role.
- T3 imports preserve all 57 roles, valid original color literals, collection metadata and the opposite appearance. Roles without a native equivalent survive export. Unknown/repeated roles, reserved identifiers, unsupported versions, invalid variants and malformed colors are rejected. Imports are previews until saved; duplicate identifiers receive a new local identifier instead of overwriting an existing theme.
- VS Code conversion requires an editor background. It derives neutral native chrome, maps supported workbench/sidebar/terminal colors, composites alpha, and selects readable foregrounds. External `include` files require a standalone merged theme. Exports use T3 JSON.
- Pi import is selected explicitly. Variable cycles, missing variables and invalid ANSI indices are rejected. Empty terminal-default values retain the native fallback. Known UI, status, message and terminal colors map into native roles; TUI-only behavior remains with Pi.
- Files are bounded to 256 KB, the library to 100 themes. The local `theme-library.json` uses atomic replacement and a previous-library `.bak`. A malformed library is preserved and saving is blocked until recovery. If no backup exists, Reset damaged library retains a copy of the broken file and starts an empty library. Writes take an exclusive file lease and reject stale state from another window; Reload library refreshes saved themes while retaining an open preview.
- Native High Contrast remains authoritative. Existing interface/composer/code/terminal typography and opacity/contrast preferences remain independent. WebView2 requires an opaque terminal canvas. Theme previews do not recreate conversations or editor controls.

The native picker uses the documented [WinUI ColorPicker](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/color-picker). Literal colors are converted to native sRGB; T3's exported OKLCH and ordinary hex/RGB/HSL inputs are supported. Native color conversion follows the color-space definitions in [CSS Color 4](https://www.w3.org/TR/css-color-4/).
