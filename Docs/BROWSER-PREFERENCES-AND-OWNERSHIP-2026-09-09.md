# Browser preferences and terminal ownership

Implements WEB-02, WEB-06 and WEB-19 against the local T3 reference `0a590fa01af66ec135d2ebf2d5542b08a37dc275`. PiStation uses Windows native process/TCP inspection and WebView2. Wire protocol **48** requires matching host and client builds.

## Server discovery

The host reads IPv4 and IPv6 listening endpoints and owning PIDs through `GetExtendedTcpTable`. A current process snapshot walks every descendant of each live terminal shell, including grandchildren such as Node started by npm. Matching listeners carry terminal identity, project, optional thread, and terminal name through the authenticated discovery contract. Idle, closed and restored terminals do not retain process ownership. An unavailable process snapshot leaves ownership unknown while discovery continues.

Results cover the host environment. Requesting a project or thread does not attribute unrelated listeners to it. Preview offers **All servers on this host** and **Owned by this thread**, with explicit ownership labels. The host validates the requested thread belongs to the project. The desktop ignores responses from a previous project/thread selection.

Discovery refreshes every three seconds while the preview server list is visible. Unchanged results preserve list items. HTTP/HTTPS probes keep existing HTML/XHTML and safe loopback redirect validation, bounds and cancellation. A 15-second probe cache includes listener PID; ownership is refreshed independently and PID changes invalidate cached probes. Owned listeners receive priority within the candidate bound. Redirect ownership requires a known final numeric loopback endpoint; a DNS alias such as localhost can be ambiguous and remains unowned. No helper PowerShell process is launched by discovery. This does not implement universal project attribution (OPT-09).

## Browser settings

Open **Settings → Integrations → Browser**:

- **Open links in:** System browser (default) or App preview. HTTP/HTTPS chat, terminal, linked-PR and workflow links share routing. Ctrl-click on a chat link forces the system browser; terminal activation modifiers retain their existing meaning. Mail links and links without a thread context use Windows. Failed app opening falls back to Windows; cancellation caused by a context change does not open the link elsewhere. The explicit preview “open externally” action remains an explicit system-browser action.
- **Default viewport:** fill available space, desktop, tablet or phone. **Default zoom:** 25–300%, using the existing preview range. **Default appearance:** system, light or dark. Defaults seed new tabs; existing and restored tabs retain their own state.
- **Profiles:** create up to 24 custom profiles, rename, choose a default, clear data and remove. Names are 1–48 characters. Renaming keeps the stable ID and storage. The built-in Default profile cannot be renamed or removed. Clear/remove require an explicit confirmation in the settings panel. Removal first awaits successful WebView2 data clearing; a clear failure retains the profile record. Deleting the default selection resets it to Default. Existing tabs keep their original profile until closed; a later restored tab whose profile was removed falls back to the current default.
- **Incognito:** choose it on a new tab before navigation. It uses WebView2 InPrivate mode and cannot be the global default. Incognito tabs and their addresses are excluded from PiStation's tab restoration and recent-address persistence. Captures or annotations explicitly saved by the user are still saved artifacts.

Browser preferences are client-local and shared by the desktop's local and remote environment windows in `browser-settings.json`. Existing local preferences seed the shared store on first use; a bounded, one-time import also retains custom profile IDs from saved remote layouts. The creation limit does not discard migrated legacy profiles. Removed profiles are not imported again on restart. Browser data stays under each environment's `browser-profiles/<hashed-profile-id>` directory. Remote windows now receive their own browser storage root; they no longer reuse the fallback local browser-automation directory. Local profile paths remain compatible. Browser preferences do not change the per-thread agent inspect/interact permission.

Clear/remove uses WebView2 `AllProfile` clearing across the selected profile's existing local and saved remote-environment directories under this desktop data root. It clears cookies, logins, cache, history and site storage, including profiles with no current tab. Other profile IDs are untouched. Open tabs remain open and can recreate data. Remote preview reload renews its app-issued connection cookie after clearing. No environment directories are recursively deleted. Old remote tabs may require signing in again after the storage isolation correction.

Agent-created tabs, additional agent browser operations, and 30/60 FPS recording remain separately tracked as WEB-14 through WEB-17 and WEB-09.
