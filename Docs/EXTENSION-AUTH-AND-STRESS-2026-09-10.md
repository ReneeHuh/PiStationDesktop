# Extension compatibility, authentication and retained stress investigations

This working tree extends the repository browser batch on `b3413a8`. Protocol **60** distinguishes extension component questions from ordinary text questions; host and client must be updated together. EXT-15 and PI-09 remain Partial. BUG-04 and BUG-09 remain investigations unless the evidence below establishes a reproduced cause and verified fix.

## Extension UI

Extension component questions now have an unwrapped Consolas text area with horizontal/vertical scrolling. The 80/100/120-column buttons change the width passed to the Pi component and invalidate it. Pointer presses and wheel input are translated into cell coordinates and SGR mouse input. Terminal input listeners can replace input data or consume it. Asynchronous `requestRender()` changes refresh the correlated native question, rather than waiting for another user answer. Unchanged frames are ignored; changed-frame refreshes are coalesced to at most approximately two per second. Components have a ten-minute total lifetime, a 120-line/12,000-character output bound and disposal on completion/cancel/reload.

`setEditorComponent`, `getEditorComponent` and `addAutocompleteProvider` now retain and invoke real extension factories. Run **`/pistation-extension-editor initial text`** to use the extension editor; without a replacement factory this uses Pi's `CustomEditor`. Registered autocomplete wraps Pi's command/file provider. Enter named keys such as Tab, Enter, Escape or Ctrl+C into the component's input and submit them. Finishing returns an editor-text proposal; the existing native **Insert into draft** action controls applying it to the composer. It never starts a model turn automatically. Reset/reload clears factories and provider registrations.

These SDK features require **Pi 0.85 or later**. During this investigation the default PATH installation reported **0.84.4**, so the existing launcher correctly omitted the adapter. Tests use the existing isolated `TestResults/pi-0.85-runtime/node_modules/@earendil-works/pi-coding-agent` installation via `PISTATION_PI_PATH`; the user's default Pi installation was not changed. The SDK integration tests now require the minimum version explicitly, so an older installation fails at discovery rather than timing out waiting for component input.

This is a native adaptation, with explicit remaining limits: ANSI colors/cursor control are stripped; terminal overlay placement and full-screen layout semantics are not reproduced; Unicode wide/combining-cell mouse accuracy is unqualified; mouse motion, dragging and button-release tracking are not implemented. The extension editor opens through the explicit command and does not replace the native composer control. Components requiring arbitrary TUI methods outside this bridge can still fail. Native pointer/rendering/accessibility acceptance remains pending. These boundaries keep EXT-15 Partial rather than claiming universal terminal compatibility.

## Fresh authentication

Provider login now runs through a shared prompt adapter. All non-selector answers use the native secret-input marker. Selector labels map back to provider option IDs; unknown answers are rejected. Cancellation and timeout abort the provider operation and clear pending sign-in status. Provider exception text is replaced with a generic failure because provider errors can echo credentials. Only valid HTTPS browser/device URLs without userinfo are offered to the browser; arbitrary provider notification text is not copied to status.

The installed-Pi test exercises isolated dummy-key login/logout for OpenAI, Anthropic, Google, Mistral and Groq. Their checked SDK API-key login implementations prompt and persist locally; they do not verify the dummy key against a service. Node fixtures cover browser/device notifications, selection, invalid URLs, cancellation, timeout and credential-bearing errors. Live OAuth redirects, device authorization, actual API-key validity, fresh Windows installation and real service access are still unverified. The user's earlier instruction to skip live sign-in remains in effect, so PI-09 and DEL-06 remain open.

## BUG-04 and BUG-09

The retained BUG-09 failure in `TestResults/code-Debug-20260909-224212-bdb21bf1/` says the browser connection ended because a task was canceled during the local slow-start heartbeat test. It predates the richer polling diagnostics and does not establish whether CPU scheduling, I/O or another delay caused the cancellation. Source inspection also found synchronous filesystem work and shared browser-operation locking as possible latency sources; these are hypotheses, not established explanations for the historical failure. The three-second client poll deadline and five-second host lease remain unchanged.

The unchanged current baseline passed **five checks**: three local/HTTPS/SSH slow-start heartbeat cases and two checkpoint checks. [Baseline log](../TestResults/compatibility-bug-baseline.log), [summary](../TestResults/code-Debug-20260911-022104-a21902e8/summary.json).

The broader run again passed all three slow-start cases. [Polling measurements](../TestResults/compatibility-heartbeat-baseline-metrics.json) show maximum replies of approximately 46 ms local, 47 ms HTTPS and 53 ms SSH, with maximum between-poll gaps of 432/331/317 ms respectively. The concurrent checkpoint test completed all three workflows in approximately 25 seconds overall: [timings](../TestResults/compatibility-checkpoint-baseline-metrics.json). These measurements do not reproduce either historical failure.

The checkpoint regression now also runs three complete, isolated two-turn/capture/rewind workflows concurrently, preserving the original filesystem, conversation and checkpoint assertions and per-flow deadline. This deliberately exercises Git/process contention and records elapsed times. It is additional stress coverage, not a product fix or proof that the original checkpoint failure is resolved. Separate overlapping heartbeat/checkpoint runs retain per-process evidence below.

## Validation

The first broad gate recorded **72 passes and five failures**, with no skips: 30 ClientRuntime and 32 Host passed; PiRpc passed nine/failed five; Protocol passed one. [Retained gate](../TestResults/compatibility-gate-1.log), [summary](../TestResults/code-Debug-20260911-022844-353799eb/summary.json). The SDK-dependent failures came from selecting Pi 0.84.4 on PATH. A [diagnostic run](../TestResults/compatibility-adapter-diagnostic.log) confirmed the missing adapter; this was an environment/prerequisite failure, not evidence that the new editor code worked.

With the isolated 0.85 runtime explicitly selected, **all seven installed-Pi desktop integration checks passed**, including the real CustomEditor/autocomplete proposal and all five dummy-key login/logout paths: [log](../TestResults/compatibility-desktop-085.log), [TRX](../TestResults/compatibility-desktop-085/desktop-085.trx). Eight Node bridge/authentication checks also passed: [log](../TestResults/extension-auth-bridge-final.log).

The final solution/WinUI build passed with zero warnings/errors, followed by **18 managed checks**, zero failures/skips: one ClientRuntime, two Host, 14 PiRpc and one Protocol. [Final gate log](../TestResults/compatibility-final-gate.log), [summary](../TestResults/code-Debug-20260911-024239-ef95e3bb/summary.json). No functional changes followed this gate.

The deliberate overlap used two separate test processes, each with `DOTNET_PROCESSOR_COUNT=2`, without a competing build. The checkpoint test ran three complete flows concurrently and passed; the local/HTTPS/SSH heartbeat tests all passed. Their execution intervals overlapped the checkpoint test by approximately 2.4/17.7/9.7 seconds respectively. Maximum observed replies were approximately 7.3/22.6/12.5 ms. [Checkpoint log](../TestResults/compatibility-checkpoint-overlap.log), [heartbeat log](../TestResults/compatibility-heartbeat-overlap.log), [timing measurements](../TestResults/compatibility-overlap/measurements.json). These four passing test cases strengthen the retained evidence but do not establish or fix either historical root cause. Both BUG-04 and BUG-09 remain open.

[Static visual contracts](../TestResults/compatibility-visual-contract.log) passed for 24 states, four responsive layouts and three text scales. [Package hashes](../TestResults/compatibility-package-check.json) match desktop/SSH Host and Protocol assemblies, plus the UI, SDK, authentication and resource scripts across source, test fixtures and both packages. No native or live-provider pass is claimed.
